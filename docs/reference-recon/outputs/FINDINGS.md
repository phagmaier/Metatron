1. **Reject destructive cleanup shortcuts.** The inspected legacy delete path treats tracked paths as the external-worktree guard without consulting creation provenance (`apps/desktop/src/lib/trpc/routers/workspaces/procedures/delete.ts:493`). A separate renderer retries a dirty-state conflict with force (`apps/desktop/src/renderer/routes/_authenticated/_dashboard/components/DashboardSidebar/components/DashboardSidebarDeleteDialog/hooks/useDestroyDialogState/useDestroyDialogState.ts:142`); the removal worker defaults to double-force (`packages/host-service/src/workers/tasks/git.ts:360`). Archived reconciliation requests `force: false` (`packages/host-service/src/runtime/archived-workspace-reconcile.ts:68`), but cleanup omits that option when calling removal (`packages/host-service/src/trpc/router/workspace-cleanup/workspace-cleanup.ts:572`). These are source-supported paths, not reproduced data loss. **Source:** [03-worktree-lifecycle.md, Findings 1–3](03-worktree-lifecycle.md#L15). **Verdict: reject** — tracking is insufficient deletion authority, changed dirty state invalidates prior consent, and ambiguous destructive work must not resume automatically. **Cost:** 0 implementation; reported M9 audit estimates are 4–8h per provenance/dirty-race area and 1–2 days for diagnostic reconciliation, overlapping other recovery work.

2. **Reject automatic session replacement as task recovery.** Automatic terminal resume calls the host without an owner ambiguity decision (`apps/desktop/src/renderer/routes/_authenticated/_dashboard/v2-workspace/$workspaceId/hooks/usePaneRegistry/components/TerminalPane/components/TerminalAgentAutoResume/TerminalAgentAutoResume.tsx:125`); an atomic candidate claim (`packages/host-service/src/terminal-agents/persistence.ts:282`) prevents competing claims but does not establish whether a prior mutation succeeded. The ACP report likewise distinguishes reopening context from replaying work. **Sources:** [01-session-recovery.md, Finding 1](01-session-recovery.md#L9), [02-acp-vs-adapters.md, Finding 7](02-acp-vs-adapters.md#L85), [04-state-surface.md, Finding 5](04-state-surface.md#L49). **Verdict: reject** — retain metatron's existing `RECOVERY_REQUIRED`/`RETRY_DECISION` barrier; neither native resume nor a fresh conversation proves safe continuation. Actual duplicate mutation is unverified. **Cost:** 0 for rejection; the reports estimate 1–2 days for decision-backed recovery and 4–6h within M8 regression for load/crash cases, not an additional recovery architecture.

## 6. Explicit rejections with reasons

- **Force escalation, imported-tree deletion authority and automatic destructive crash replay:** rejected in finding 1; risk of irreversible loss overrides cleanup convenience.
- **Automatic native/chat resurrection as task recovery, or timeout as permission to retry:** rejected in finding 2; transport recovery cannot settle an ambiguous mutation.
- **Unrestricted defaults, first-option denial fallback, and shared-workspace writer authority:** rejected in findings 3–4; native restrictions, server policy and attempt leases remain necessary.
- **All-four ACP replacement, ACP as auth bypass, or ACP as task/budget authority:** [02, Findings 1, 6 and 8](02-acp-vs-adapters.md#L11) establish no installed parity, approved auth route or portable orchestration guarantee. Reject wholesale replacement; only finding 8's gated OpenCode trial proceeds as a recommendation.
- **Silent settings fallback, malformed completion treated as success, or silent fresh-session continuation:** reject the behaviors identified in [02, Findings 4–5 and 7](02-acp-vs-adapters.md#L52); unconfirmed configuration/history must remain explicit.
- **Pane disappearance or renderer reload as proof that work stopped/recovered:** findings 5–6 and [04, Finding 9](04-state-surface.md#L89) require durable domain evidence.
- **Advanced docking, application-wide version gates as a blocker inbox, and cloud/mobile/relay/marketing/telemetry/PR-remote proposals:** excluded by task scope; [04, Finding 10](04-state-surface.md#L99) also finds unnecessary complexity and possible unrelated-task blocking. No proposals for these systems survive the merge.
