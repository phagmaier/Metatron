# M9 item 3 — local safety audit

Scope: spec §§4.4, 8, 12, 13.4 and 15; owner HTTP API, session MCP gateway, native file policies, persisted adapter diagnostics, candidate capture and local integration. This is a source and disposable-fixture audit, not a penetration-test or OS-sandbox claim. Existing live A–G evidence remains separate and unchanged.

| Boundary | Findings and verification |
| --- | --- |
| Permissions | `gateway/mcp.ts` binds random bearer credentials to a session/run/task/role and revokes them at shutdown. `orchestration/policy.ts` and `tools.ts` enforce role, run, current attempt, task ownership and mode. Scheduling and integration recheck server-side policy; owner approval cannot grant shell, delegation or unsafe paths. Existing gateway, scheduler, native-approval and integration tests cover forged scopes, worker scheduling, Chat/Plan, quotas, owner-only approval and replay. |
| Paths | **Fixed:** Pi's `physicalPath` ENOENT fallback accepted dangling file/parent symlinks before a write could follow them outside the worktree. Pi now translates its native tools into the shared component-by-component file policy, capturing its startup root once. It also inherits canonical-root, regular-file, permission and search-selector checks. App worktree paths and ownership manifests are validated outside the source checkout; production static serving accepts only the entry page and flat built assets. |
| Cross-site access | Loopback-only socket, exact Host and Origin, opaque-Origin/cross-site refusal, no CORS allowance, and process-random mutation token remain intact. Added wire-level checks for the token endpoint, SSE and MCP, including absent Origin with cross-site Fetch Metadata. Existing API checks exercise a correct token paired with a foreign Origin, missing/wrong token, body/schema validation and token rotation. No server defect was found here. |
| Logs | **Fixed:** Codex tool-start/tool-finish summaries included raw shell commands (which may contain credentials); summaries now retain the category and lifecycle only. Native stderr is discarded and provider/protocol errors use fixed diagnostic categories; raw tool inputs/results are not journaled as tool summaries. Existing adapter tests use inert secret canaries. Model-authored text/reports and owner-declared test-command output are deliberately retained and can contain whatever those producers emit; they are not automatically scrubbed. |
| Secrets | **Fixed:** one shared sensitive-path list now covers Git credential/config stores, Codex/Claude/OpenCode config trees, dotted credential files, cloud/SSH stores, additional private-key names and keystore suffixes. Candidate capture refuses these even when explicitly declared; it records path/status evidence rather than their contents. Unknown new files, ignored declarations, symlinks and special files still block. Name filtering cannot discover arbitrary embedded secrets in ordinary source. |
| Git defaults | **Fixed:** hidden index flags could defeat clean-checkout checks; they now cause refusal during inspection and immediately before apply. An inert clean filter executed during status inspection; all app Git calls now refuse configured executable filters/merge drivers before running the requested operation. An implicit union default is overridden with the text driver so conflicts remain visible. Existing tests cover dirty/ignored-file protection, separate writer worktrees, review binding, branch/base drift, conflicts, owner approval, compare-and-swap, and crash/restart without replay. [Decision and compatibility limits](adr/2026-10-18-git-checkout-safety.md). |

Regression sources: [security-audit.test.ts](../tests/security-audit.test.ts), [integration-drift.test.ts](../tests/integration-drift.test.ts), [server.test.ts](../tests/server.test.ts). The first five audit tests failed against the prior behavior; clean-filter and custom-merge-driver refusal tests also failed before their fixes. A first HTTP-test draft used Node Fetch, which discarded a forged Host header; raw `node:http` requests corrected the test without a server change. Failed disposable test roots were retained by the normal test harness.

The final changed-file scan found no exact credential values from the current process environment in the 17 edited/new files. This is a bounded exclusion check, not a general secret detector. Evidence JSON was parsed separately: an explicit Biome invocation reported those paths ignored by the repository configuration, while the standard code lint passed.

Known limits retained: Codex Lead/read-only workers can read outside the assigned checkout; native tool permissions and worktrees are not a hostile-code sandbox; other processes can race filesystem/branch checks; previously persisted model/native transcripts are not rewritten. OpenCode's refused-tool turn-loss issue remains open in `todo.md`; no OpenCode protocol/permission change was attempted in this audit. Configured executable Git drivers and hidden/sparse index state now require a compatible checkout before the app proceeds.

Validation results and commands are recorded in [progress.md](progress.md). [Pi startup evidence](evidence/m9-security-pi-startup.json) is a native-loader/guard-registration check with **zero model prompts**, not a live reader/writer run. An earlier optional `PiAdapter` model-configured startup check was **BLOCKED** by the empty catalog in its fresh, unauthenticated app home; that state and an optional native-login command are recorded in the evidence. The loader check requires no credentials and passed on installed Pi 1.3.0. No personal login was read/copied. Cost-bearing harness turns are intentionally omitted for this audit.
