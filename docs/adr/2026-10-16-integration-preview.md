# M5: isolated integration preview

## Context

Spec §8.6 steps 1–2 require deterministic checks (`git diff --check`, declared tests, no unresolved changes) in an isolated integration worktree based on a recorded destination SHA, never the owner's possibly dirty checkout. No test command had been declared anywhere in the domain, and reviewers and workers cannot run shell commands. Drift/conflict handling, owner approval and application to a branch are later M5 items.

## Decision

- **Owner-only preview.** `POST /api/tasks/integration` (task card **Prepare integration preview**) accepts an implementation task, an optional local destination branch (default: the run's starting branch; never `lao/*`) and up to 8 test commands. No Lead or worker tool reaches it, and Chat/Plan is denied. The current revision's latest candidate must have a latest independent review recommending `pass`. A preview grants no approval and changes no task or candidate status.
- **Destination verification before Git mutation.** The engine reads exactly `refs/heads/<branch>` and requires it to equal the candidate base. It also requires the create-only candidate branch to still match its record. Either failure is recorded with no worktree or branch created. Merging onto a moved destination and conflict handling are left to the drift/conflict item (superseded by the [drift/conflict ADR](2026-10-16-integration-drift-conflicts.md): drift is now merged in isolation, not failed).
- **Isolated worktree.** After the destination SHA and path are durable, `git worktree add -b lao/integration-<id>` creates an app-owned worktree at that SHA under `<data>/worktrees/`, with an ownership marker. The candidate is applied there with `git merge --ff-only`. Checks: HEAD/branch/clean state, integrated file list identical to the reviewed candidate with no secret-sensitive path, and `git diff --check`. The final diff is saved as a reference artifact. The destination is rechecked at the end.
- **Targeted tests are owner-declared argv commands**, run without a shell in the integration worktree, sequentially, with a per-command timeout (default 600 s, maximum 3600 s). Each command gets its own process group, which is terminated on timeout, on app shutdown and after the leader exits, so helpers the command started cannot keep writing. Output (the last 256 KiB) is a log artifact. The environment is reduced to PATH/HOME/locale/XDG-style variables, so provider keys in the app's environment are not passed on. **This is not a sandbox:** agent-written code runs with the owner's OS permissions and can read the home directory. Test-written files remain in the scratch worktree; the verified result is the integration commit.
- **Persistence/recovery.** Migration v6 adds `integrations` (one worktree path per preview; a partial unique index allows one `preparing` preview per task). Progress is saved only while preparing, and every step is journaled (`integration.*`). Shutdown stops tests and marks the preview `interrupted`. Startup marks any leftover `preparing` preview `interrupted` and never resumes or reruns it. Worktrees, branches and artifacts are always retained.

## Consequences

The owner can see a verified integration result and declared test outcomes without risk to their checkout or branches. Any destination movement currently fails the preview, until the drift/conflict item adds merge previews and `BLOCKED_CONFLICT`. Approval, final revalidation and application, review UI, and cleanup of retained integration worktrees are later items. Running tests needs whatever the repository requires (e.g. an install command declared first). A helper that calls `setsid` itself can escape group termination. No dependency, toolchain or spec change.
