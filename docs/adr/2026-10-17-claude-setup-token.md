# Claude owner-supplied setup-token compatibility

Date: 2026-10-17. Scope: M8 item 1, Slice A. Supersedes only the API/provider-only authentication decision in [Claude worker permissions](2026-10-17-claude-worker-permissions.md); its other invariants remain unchanged.

## Context

The owner intends native subscription authentication, not separate API billing by default. [Official CLI authentication](https://code.claude.com/docs/en/authentication#generate-a-long-lived-token) documents `claude setup-token` and `CLAUDE_CODE_OAUTH_TOKEN` for unattended scripts. The [SDK quickstart](https://code.claude.com/docs/en/agent-sdk/quickstart) restricts third-party developers offering claude.ai login/rate limits for products unless previously approved. Neither page establishes an explicit personal-use exemption or a blanket prohibition on every local personal integration. Mechanism support is not vendor approval.

## Decision

- The owner explicitly selected setup-token compatibility for this local app, acknowledged unresolved SDK-product policy applicability, and authorized a bounded sonnet/low disposable smoke: read, resume, denial, approved write/independent denial, and active cancellation. No automatic retries. Owner authorization is not Anthropic approval; resolve applicability/obtain approval where required before using or distributing subscription-backed SDK products.
- Forward only the owner-supplied `CLAUDE_CODE_OAUTH_TOKEN` in addition to existing API/provider variables. Never extract personal credentials, reuse ambient login state, or change global settings/sessions. Keep app-owned config/transcripts and existing worker policy hooks.
- Deliver the secret privately through the app's process environment, never chat, evidence, source or command arguments. The CLI owns token generation/browser authorization. The owner later explicitly authorized a one-off private file handoff for this validation: verify owner/modes (0700 directory/0600 file), read without displaying, inject only into the test child environment, then remove the file/directory. This is not extraction from personal credentials, persistent application credential storage or a new login UI.
- Preserve native precedence: selected cloud route, then API key, then setup-token among admitted variables. Never remove a key to force subscription usage or silently switch to separate API billing. A configured subscription route consumes allowance and can be subject to limits/extra usage; it is not promised free.
- Classify using the owned child's environment snapshot and native account metadata. Confirmed source means `authenticated: "unknown"`, not entitlement. Absent routes and metadata mismatches prevent model submission; metadata initialization failures remain safely diagnosed and never authorize a prompt. Profile gates remain unchanged.

## Consequences and evidence

Initial inert no-model probes observed the installed source spellings and precedence but proved no entitlement. The owner then supplied a real setup-token through the explicitly authorized private temporary handoff. Actual-worker discovery selected setup-token, followed by a successful five-turn native smoke on disposable app/Git state: streaming read, same-ID clean resume, denial/cancel, approved Write plus independent denial/stale-grant refusal, and active-generation cancellation. [Native receipt](../evidence/m8-claude-native-live.json). Sonnet resolved to `claude-sonnet-5-5`; native hooks proved `low` effort because headless init omits that field. Successful turns required authoritative results and owned exit 0; active cancellation produced interrupted status/owned exit 143, never inferred success. The temporary credential was removed; receipt copies passed exact-secret exclusion checks. This proves technical access at that time, not vendor approval, free usage or future entitlement.

The real run exposed bundled skills/plugins that empty SDK lists did not suppress. Disable bundled/synced skills and plugin sync, use the documented disable-slash-commands flag, and explicitly disable the three observed built-in plugin IDs through inline `enabledPlugins`. Keep the zero-skill/zero-plugin init guard; unfamiliar future plugins still fail closed. Do not use `--bare` as a shortcut: installed help explicitly limits its first-party authentication to API key/helper. For headless effort, accept omitted init metadata only with subsequent native PreToolUse/Stop proof; a mismatching/missing tool proof denies the operation, and unproven effort prevents success. No file/permission/checkout/recovery policy is widened.
